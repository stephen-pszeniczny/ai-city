## Addendum: Phase 1a plan (planning session, no code)

**Done**
- Checked the tools the stack needs: Python 3.13, Node, npm, Git, GitHub CLI, gitleaks, SQLite, Xcode/Swift, Ollama. Nothing missing, nothing installed. uv, pnpm and pipx aren't needed (built-in `venv` + `pip`, and `npm`).
- Planned the Phase 1a architecture, the Personal/Sample isolation design, Touch ID, and the session breakdown. Approved by Steve.

**Architecture**
- Backend: FastAPI package in `src/aicity/` (`config`, `security`, `db`, `mode`, `auth`, `routers/`, `services/`, `migrations/`). Pure logic lives in `services/` so it's easy to test: money, fx, pay_schedule, bank_csv, deposit_match, stale, reminders.
- Frontend: Vite + React + TypeScript + React Three Fiber in `frontend/`.
- Serving: the Vite dev server proxies `/api` while building. For daily use, FastAPI serves the built page and the API on `127.0.0.1:8765`, kept running by a launchd LaunchAgent and added to the Dock from Safari.
- SQLite schema, the same in both databases: `meta` (holds `db_kind`), `tasks`, `task_events`, `notifications`, `imports`, `bank_transactions` (every statement row, deduplicated by row hash), `day_job_pay`, `side_work_entries`. Money is stored as integer cents; exchange rates as exact text.
- Bank chequing CSV: the header must match exactly, amounts are parsed with `Decimal`, and errors report row numbers only, never row contents. The income tracker reads deposits only, and deposit matches are suggested for Steve to confirm. Matching rules live in the local settings file.
- Private settings (platforms, pay rhythms, matching rules, location, goals, reminder default, stale thresholds) live in `<data folder>/settings/settings.toml`. The repo ships `settings.example.toml` with invented values only.

**Decisions**
- Data folder comes from `AICITY_DATA_DIR`, defaulting to the private data folder. Tests must never touch the real folder.
- `tests/conftest.py` sets `AICITY_DATA_DIR` to a temp folder only if it isn't already set, then always runs a guard that stops the run if the folder resolves to `$HOME/AI-City-Data` or inside it. A test proves the guard trips by running pytest in a subprocess with `HOME` and `AICITY_DATA_DIR` both pointed inside a temp folder.
- Test settings are built in `conftest.py`. `tests/fixtures/` holds only the fake bank chequing CSV. `.gitignore` is unchanged.
- Personal/Sample isolation: one function (`get_db()`) opens databases; the mode is read once per request; each file's `db_kind` label must match the mode; no `ATTACH`; personal-only actions are refused in Sample; full page reload on switch; mode persisted across restarts. Isolation tests use temporary databases only.
- Cross-site protection: Host-header check, and every non-GET request must carry the app's own `Origin` (dev origin allowed only with `AICITY_DEV=1`). GET never changes data. The unlock cookie is `HttpOnly`, `SameSite=Strict`, and its token is held only in server memory. All of this is tested.
- Touch ID through a small Swift helper using LocalAuthentication, chosen over a WebAuthn passkey because passkeys sync through iCloud Keychain or Google Password Manager. The helper stores nothing. Fallback is the app password, stored as a scrypt hash in the data folder. Finance relocks after 15 minutes idle and on mode switch or restart. No Finance lock in Sample mode.
- Pay timing supports weekly, biweekly and monthly rhythms. The example file and tests use invented rhythms; tests cover several rhythms and edge cases (month and year boundaries, leap day, daylight saving, short months).
- Blocked-words pre-commit check: the hook reads a word list Steve keeps in the data folder, prints only file name and line number on a match, and fails if the list is missing. The list never appears in the repo.
- Robot interior moved to Phase 1b. In 1a, clicking a building opens a glass panel with its modules.
- Handoff notes keep dated file names; their contents refer to session numbers only.
