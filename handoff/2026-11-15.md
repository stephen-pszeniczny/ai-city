## Decisions made
- Library versions: newest release at least 14 days old when pinned (same rule for GitHub Actions). Reduces the risk of a bad or tampered fresh release.
- No installable Python package: avoids an unapproved build tool; pytest finds the code through `pythonpath`.
- npm install scripts turned off in `frontend/.npmrc`: common supply-chain protection; none of the packages needed one.
- Settings file covers only what's needed now. Side-work platforms, pay rhythms and deposit-matching rules move to sessions 6–7, with the code that uses them.
- Building IDs are job names (`planner`, `finance`, `jobs`, …); display names live only in settings.
- Migrations tracked with SQLite's built-in `user_version`; new databases built under a unique temp name and moved in with `os.link` (never overwrites).
- Blocked-words matching: case-insensitive, whole words where only letters count as word characters (catches words next to `_`, digits, punctuation; not inside longer words; not camelCase). An empty list counts as missing and blocks commits.
- Approved extras: the blocked-words check also covers commit messages and staged file names, and hides any file name that contains a blocked word.
- CSS colours with transparency are written with commas (`rgba(255, 255, 255, 0.08)`): the space-separated form trips the secret scanner's SIN rule.
- Prettier line length set to 100 to match ruff.
- GitHub CLI login given the `workflow` scope (needed to push workflow files).
