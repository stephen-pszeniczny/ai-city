# Week Plan (PR 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mission Control's Daily plan app shows a saved Monday–Sunday week built from fixed blocks in settings, with gym Done/Skipped, block add/edit/remove, "Rebuild this week", and a Today list of due to-dos.

**Architecture:** Fixed block rules live in the private settings (`[[plan.blocks]]`). A pure function turns rules into one week's blocks; `PlanStore` saves weeks and blocks in two new tables (migration 010) and applies edits and the rebuild rule. New routes under `/api/plan` follow `task_routes.py`. The frontend adds a `PlanPanel` to the Mission Control desktop; pure helpers in `frontend/src/plan/week.ts` carry the logic that gets tested.

**Tech Stack:** Python 3.13, FastAPI, SQLite (STRICT tables), pytest; React + TypeScript, node:test.

**Spec:** `docs/superpowers/specs/2026-11-19-week-plan-checkin-routines-grocery-design.md` (PR 1 of 4 in its build order).

## Global Constraints

- Public repo: example values only in tracked files; real hours and events never in code, tests, fixtures or docs. The main job shows only as "Work".
- Settings parsed strictly like the rest of `settings.py`: unknown keys refused, error messages name the setting, never repeat its value.
- Tables are `STRICT`, refuse bad data with CHECKs, and rows are never deleted ("removed" is a status).
- Every GET route only reads (`tests/test_get_routes_read_only.py` checks automatically). Creating a week happens on a POST.
- Weeks run Monday to Sunday. Times are local `HH:MM`, 24-hour, `end > start`, no block past midnight. "Today" is the Mac's local date (`clock().astimezone().date()`, as `vault_routes._today`).
- Mission Control needs no Touch ID.
- Sample mode never reads the private settings: it uses `sample_data.SAMPLE_PLAN`.
- No new dependencies.
- Not in this PR: check-in screen and reminder, usual events, grocery day, routines, grocery list, badge.

## Review Focus

1. **Editing a past day** (yesterday's block): refused by the server with a clear message; only gym Done/Skipped is allowed, and only for the last 7 days, never for a future day. Test in Task 4.
2. **Rebuild after Steve removed or changed a block**: a removed Gym never returns, an edited Work stays as edited, a done gym stays done, past days unchanged. Test in Task 4.
3. **Settings without `[plan]`** (Steve hasn't added it yet): the app shows "Add a [plan] section to your settings" instead of an error, and the rest of the app works. Test in Task 5.
4. **Opening a week far ahead or far back**: weeks after next week aren't created; a past week that was never saved shows as empty, not created after the fact. Test in Task 5.
5. **A block typed with end before start, or an empty title**: refused by the route with a 422 naming the field, and by the database CHECK if a bug skips the route. Tests in Tasks 2 and 5.

### Task 3: Building a week and reading it (`PlanStore`)

**Files:**
- Create: `src/aicity/plan.py`
- Test: `tests/test_plan.py`

**Interfaces:**
- Consumes: `BlockRule`, `PlanSettings` (Task 1); tables (Task 2).
- Produces (in `aicity.plan`):
  - `class PlanError(ValueError)`, `class BlockNotFound(LookupError)`
  - `def monday_of(day: date) -> date`
  - `@dataclass(frozen=True) class NewBlock: day: date; start: time; end: time; title: str; kind: str; settings_key: str`
  - `def blocks_for_week(rules: PlanSettings, week_start: date) -> list[NewBlock]`: for each rule and each of its days, one block; `settings_key = f"{kind}|{title}"`; sorted by day, then start.
  - `@dataclass(frozen=True) class Block: id: int; day: str; start: str; end: str; title: str; kind: str; source: str; status: str; edited: bool`
  - `@dataclass(frozen=True) class Week: week_start: str; checked_in: bool; days: list[tuple[str, list[Block]]]` (always 7 days, Monday first; removed and replaced blocks left out; each day's blocks sorted by start, then id)
  - `class PlanStore`, `__init__(self, conn, *, clock: Callable[[], datetime] = utc_now)`:
    - `get_week(self, week_start: date) -> Week | None`: None if not saved.
    - `ensure_week(self, week_start: date, rules: PlanSettings, today: date) -> Week | None`: if saved, returns it; if not saved and `monday_of(today) <= week_start <= monday_of(today) + 7 days`, creates it from `blocks_for_week` in one transaction (`with_transaction(..., immediate=True)`), so two calls never make two weeks; otherwise returns None (past weeks are never created later). Raises `PlanError` if `week_start` isn't a Monday.

### Task 4: Edits, gym Done/Skipped, rebuild

**Files:**
- Modify: `src/aicity/plan.py`
- Test: `tests/test_plan.py`

**Interfaces:**
- Produces (methods on `PlanStore`; all take `today: date` and raise `PlanError` with a plain message, or `BlockNotFound`):
  - `add_block(self, week_start: date, day: date, start: time, end: time, title: str, kind: str, today: date) -> Block`: `source='added'`; kind any of the seven except none; week must be saved.
  - `edit_block(self, block_id: int, today: date, **fields) -> Block`: fields from `day, start, end, title, kind`; sets `edited=1` on settings blocks; new `day` must stay in the same week.
  - `remove_block(self, block_id: int, today: date) -> Block`: `status='removed'`.
  - `set_gym(self, block_id: int, status: str, today: date) -> Block`: `status in ('planned','done','skipped')`; gym blocks only.
  - `rebuild_week(self, week_start: date, rules: PlanSettings, today: date) -> Week`
- Rules (messages are user-facing copy):
  - add/edit/remove on a block whose day (or new day) is before `today` → `PlanError("Past days can't be changed.")`
  - `set_gym` when the day is after `today` → `PlanError("Gym can only be marked on or after its day.")`; more than 7 days before `today` → `PlanError("Gym can only be marked for the last 7 days.")`
  - editing or gym-marking a removed block → `PlanError("That block was removed.")`
- Rebuild algorithm (the design's matching rule):

```
for each day in the week with day >= today:
    keep = blocks that are source='added', or edited, or status in (done, skipped, removed)
    (status 'replaced' rows are ignored entirely)
    touched_keys = settings_key of kept settings blocks
    mark replaced: settings blocks that are planned and not edited
    insert: blocks_for_week(rules) for that day whose settings_key not in touched_keys
```
