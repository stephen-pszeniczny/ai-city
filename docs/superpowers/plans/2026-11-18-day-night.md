# Day and Night Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 3D belt switches between day and night at local sunrise and sunset (with an Auto / Day / Night override), and shows a moon in its real phase at night.

**Architecture:** A pure Python module works out sun times and moon phase from the private settings' `[location]`; `GET /api/daylight` serves the answer. The page combines that with the override (kept in browser storage) to decide day or night, and the shared space scene fades its lights, stars, sun, Earth and a new moon between the two looks.

**Tech Stack:** Python 3 + FastAPI + pytest (backend); React + TypeScript + Three.js via React Three Fiber, `node --test` (frontend).

**Spec:** `docs/superpowers/specs/2026-11-18-day-night-design.md` (and SPEC.md section 7, "The belt").

## Global Constraints

- No location, city or coordinates in tracked code, tests, docs or screenshots. Tests use the example location from `settings.example.toml` (51.4779, 0.0, Europe/London) and other public reference places only.
- No internet feed: all sun and moon maths runs locally. No new dependencies.
- The interface panels don't change between modes (black base, royal blue accent); only the 3D scene does.
- Every "how much" number goes in `frontend/src/belt/look.ts`.
- Reduced motion: switch instantly, no fade.
- Browser storage only for the override (a per-viewer convenience); every read and write in try/catch, and missing or bad values mean Auto.
- No visual layout tests (SPEC section 10).
- After code changes run `graphify update .`. Run `graphify query` before reading source to explore.

## Review Focus

1. **Engine down or settings file missing:** the belt still renders (in day), and the override still works. Pinned in Task 3 (`isNight` with no daylight data) and Task 2 (503 on missing settings).
2. **Browser storage blocked, throwing or holding junk:** the override reads as Auto and nothing crashes. Pinned in Task 3.
3. **Mac asleep or tab hidden across sunset:** when it comes back, the page asks again soon, even if `next_change` is already past. Pinned in Task 3 (`msUntilRefresh` clamps a past time to the minimum).
4. **A place with no sunrise or sunset that day (polar night or midnight sun):** the route answers with nulls and the right `is_night`, never an error. Pinned in Tasks 1 and 2.
5. **"Today" means the location's day, not UTC's or the Mac's:** in the evening west of Greenwich the UTC date has already rolled over. Pinned in Task 1 (Vancouver evening test) and the daylight-saving changeover test.

### Task 1: Sun and moon maths

**Files:**
- Create: `src/aicity/sky.py`
- Test: `tests/test_sky.py`

**Interfaces:**
- Consumes: `aicity.settings.Location` (`name`, `latitude`, `longitude`, `timezone`).
- Produces:
  - `@dataclass(frozen=True) class SunTimes: sunrise: datetime | None; sunset: datetime | None; always: Literal["day", "night"] | None` (both times timezone-aware in the location's zone; when the sun never rises or never sets that day, both are None and `always` says which).
  - `sun_times(day: date, latitude: float, longitude: float, tz: ZoneInfo) -> SunTimes`
  - `moon_phase(at: datetime) -> float`: 0 = new, 0.5 = full, in [0, 1).

- [ ] **Step 3: Implement `src/aicity/sky.py`.** Sun: the NOAA general solar position method (fractional year → equation of time and declination → hour angle for zenith 90.833°); `cos(hour angle) > 1` means always night, `< -1` always day. Work out UTC minutes from the formula, then convert to the location's zone for the given local `day`. Moon: mean synodic month `29.530588853` days from the reference new moon `2000-01-06 18:14 UTC`, result mod 1. `daylight_at`: convert `now` to the location's zone first, take that local date, then: before sunrise → night, next change = sunrise; between → day, next = sunset; after sunset → night, next = tomorrow's sunrise; polar → `always`, next = next local midnight. **Interfaces:**
- Produces in `api.ts`: `type Daylight = { is_night: boolean; sunrise: string | null; sunset: string | null; next_change: string; moon_phase: number }`; `getDaylight = () => request<Daylight>("GET", "/api/daylight")`.

  - `type SkyChoice = "auto" | "day" | "night"`
  - `nextChoice(c: SkyChoice): SkyChoice` (auto → day → night → auto)
  - `isNight(choice: SkyChoice, daylight: Daylight | undefined): boolean`
  - `loadChoice(storage: Pick<Storage, "getItem"> | null): SkyChoice` / `saveChoice(storage: Pick<Storage, "setItem"> | null, c: SkyChoice): void` (key `"aicity.sky"`)
  - `msUntilRefresh(nextChange: string, nowMs: number): number` (clamped to [60 000, 21 600 000])
  - `blend(from: number, to: number, elapsedS: number, fadeS: number): number` (smoothstep ease; `fadeS <= 0` returns `to`)
  - `CHOICE_LABELS: Record<SkyChoice, string>` = `{ auto: "Auto", day: "Day", night: "Night" }`
